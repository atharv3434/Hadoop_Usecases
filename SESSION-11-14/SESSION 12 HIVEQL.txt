4. Hive Tables

The two important Hive table types are:
1. Managed Table
2. External Table

4.1 Managed Table

A managed table is a table where Hive manages the table's data and metadata.

// Example
CREATE TABLE flights (
    flight_id INT,
    airline STRING,
    source STRING,
    destination STRING,
    ticket_price DOUBLE
);

//Conceptually:
Managed Table
      |
      +---- Metadata → Hive Metastore
      |
      +---- Data → Hive-managed location

When a managed table is dropped, Hive normally removes its associated data as well.

4.2 External Table

An external table allows Hive to manage the metadata while the underlying data remains at an external location.

// Example


CREATE EXTERNAL TABLE flights_external (
    flight_id INT,
    airline STRING,
    source STRING,
    destination STRING,
    ticket_price DOUBLE
)
LOCATION '/airline/raw/flights';


//Conceptually:
External Table
      |
      +---- Metadata → Hive Metastore
      |
      +---- Data → External HDFS location


Dropping the external table normally removes the Hive metadata but leaves the underlying external data.

// Interview Question

Q: What is the difference between Managed and External tables?

Answer:

A managed table is controlled by Hive for both metadata and table data. An external table allows Hive to manage the metadata while the underlying data is maintained at an external location.

# 5. Partitioning
Partitioning divides a large table into smaller logical sections based on the values of one or more columns.

//Common partition columns:
year
month
date
region


// Why Partition?
Suppose an airline has:
1 TB of flight data
If the data is partitioned by year:
flight_data
    |
    +--- year=2024
    +--- year=2025
    +--- year=2026


A query for 2026 can potentially read only the relevant partition instead of scanning all years.

This is called partition pruning.

// Example
CREATE TABLE flights_partitioned (
    flight_id INT,
    airline STRING,
    source STRING,
    destination STRING,
    ticket_price DOUBLE
)
PARTITIONED BY (flight_date STRING);


//Insert into a partition:
INSERT INTO flights_partitioned
PARTITION (flight_date='2026-10-01')
VALUES
(1001, 'IndiGo', 'Bangalore', 'Delhi', 5500);


//Query a particular partition:
SELECT *
FROM flights_partitioned
WHERE flight_date = '2026-10-01';

// Interview Question
Q: Why is partitioning used in Hive?

Answer:
Partitioning divides large datasets into smaller sections. When a query filters using the partition column, Hive can avoid scanning irrelevant partitions, reducing the amount of data read.

6. Bucketing
Bucketing divides table data into a fixed number of buckets using the hash of a column.

// Example
CREATE TABLE flight_buckets (
    flight_id INT,
    airline STRING,
    source STRING,
    destination STRING,
    ticket_price DOUBLE
)
CLUSTERED BY (airline)
INTO 4 BUCKETS;

//Conceptually:
Flight Data
    |
    +--- Bucket 0
    +--- Bucket 1
    +--- Bucket 2
    +--- Bucket 3


The bucket is determined using hashing on the specified column.
// Partition vs Bucketing

| Partitioning                       | Bucketing                                               

| Based on column values             | Based on hashing                                        |
| Number depends on partition values | Fixed number of buckets                                 |
| Creates partitions/directories     | Creates buckets/files                                   |
| Useful for partition pruning       | Useful for data organization and certain joins/sampling |

// Interview Question

Q: What is the difference between partitioning and bucketing?

Answer:

Partitioning divides data based on column values, whereas bucketing divides data into a fixed number of buckets using hashing on a specified column.

Answer:

7.3 Indexing

// Important Interview Note

Traditional Hive indexing was designed to speed up searches on particular columns.

For example, conceptually, if an index existed on `flight_id`, a query such as:


SELECT *
FROM flights
WHERE flight_id = 1005;


could use the index to avoid scanning all rows.

However, traditional Hive indexing was removed starting with Hive 3.0. Apache Hive specifically documents this removal under HIVE-18448.

Since our lab uses Hive 3.1.3, students should not try to create a traditional Hive index using `CREATE INDEX`.

// Old Hive Index Syntax — Theory Only

Older Hive versions supported syntax such as:


CREATE INDEX flight_id_index
ON TABLE flights (flight_id)
AS 'COMPACT';


And:
SHOW INDEX ON flights;


However, this traditional indexing feature is not available as a normal Hive 3.x feature.

// What is used instead?

Modern Hive provides other mechanisms for efficient analytical queries, including:


Partitioning
Bucketing
ORC
Parquet
Predicate Pushdown
Materialized Views

Apache Hive specifically identifies columnar formats such as ORC and Parquet as alternatives that can perform selective scanning, and Hive 3.0+ supports materialized views.

// Practical Modern Example

Suppose the airline data is stored as ORC:
CREATE TABLE flights_orc (
    flight_id INT,
    airline STRING,
    source STRING,
    destination STRING,
    ticket_price DOUBLE
)
STORED AS ORC;


Then:
SELECT *
FROM flights_orc
WHERE airline = 'IndiGo';


ORC supports selective reading and internal row indexes/bloom filters, helping reduce unnecessary data scanning.

// Interview Question

Q: Does modern Hive support the traditional CREATE INDEX feature?

Answer:

No. Traditional Hive indexing was removed in Hive 3.0. In modern Hive, techniques such as partitioning, bucketing, ORC/Parquet columnar storage, predicate pushdown, and materialized views are used for query optimization.

// Very Important for Students

Do not say:

> "Hive uses CREATE INDEX for indexing."

For a Hive 3.1.3 interview, say:

> "Traditional Hive indexes were removed from Hive 3.0. Modern Hive uses partitioning, bucketing, columnar formats such as ORC and Parquet, and other query optimization techniques."

# 8. Storage Formats

Hive supports several storage formats.
//Important formats:
FILE
SEQUENCEFILE
ORC
PARQUET
AVRO

//8.1 FILE

 is simple and easy to inspect.

// Example
CREATE TABLE flights_ (
    flight_id INT,
    airline STRING,
    ticket_price DOUBLE
)
STORED AS FILE;


Suitable for simple input and learning, but generally less efficient than columnar formats for large analytical workloads.

# 8.2 ORC

ORC = Optimized Row Columnar

ORC is a columnar storage format designed for efficient Hive analytics.

// Example


CREATE TABLE flights_orc (
    flight_id INT,
    airline STRING,
    ticket_price DOUBLE
)
STORED AS ORC;


//Advantages:
Compression
Column pruning
Predicate pushdown
Efficient analytical queries

# 8.3 Parquet

Parquet is a columnar storage format widely used in Big Data analytics.

// Example
CREATE TABLE flights_parquet (
    flight_id INT,
    airline STRING,
    ticket_price DOUBLE
)
STORED AS PARQUET;
// Interview Question

Q: Why are ORC and Parquet preferred for analytical workloads?

Answer:

They are columnar formats that support efficient storage, compression, and reading only the required columns, which can reduce I/O during analytical queries.

# 9. Importing Data

Hive can load data from the local filesystem or HDFS.
//Suppose we have:
/home/sari/flights.csv

//Use:
LOAD DATA LOCAL INPATH '/home/sari/flights.csv'
INTO TABLE flights;

//Here:
LOCAL
  ↓
Local Linux filesystem


// Loading Data from HDFS

Suppose the file is:
/airline/input/flights.csv
//Use:
LOAD DATA INPATH '/airline/input/flights.csv'
INTO TABLE flights;
//Here:
No LOCAL
     ↓
HDFS path


// Interview Question

Q: What is the difference between LOCAL and non-LOCAL in LOAD DATA?

Answer:

`LOCAL` indicates that the source file is on the local filesystem. Without `LOCAL`, the source path refers to a Hadoop/HDFS location.



# 10. Importing Data into a Partition

For a partitioned table:
LOAD DATA INPATH '/airline/input/flights.csv'
INTO TABLE flights_partitioned
PARTITION (flight_date='2026-10-01');
The data is loaded into the specified partition.

`ALTER TABLE` is used to modify table definitions or properties, such as renaming a table, adding columns, or adding partitions.

13. TRUNCATE vs DROP

This is an important interview question.

// TRUNCATE

Removes the data but keeps the table.
TRUNCATE TABLE flights;
//Concept:
Table
  |
  +--- Data removed
  |
  +--- Table remains


// DROP

Removes the table.
DROP TABLE flights;
//Concept:
Table
  |
  +--- Metadata removed
  |
  +--- Table no longer exists


// Interview Question

Q: Difference between DROP and TRUNCATE?

Answer:

`TRUNCATE` removes the rows while retaining the table structure. `DROP TABLE` removes the table itself, including its metadata.

# 17. Most Important Interview Questions

// Q1. What is Hive?

Hive is a data warehouse and SQL-like query system in the Hadoop ecosystem, mainly used for large-scale data analytics.

// Q2. What is HiveQL?

HiveQL is the SQL-like query language used to create, manage, and query Hive tables.

// Q3. Managed vs External Table?

Managed tables have their data and metadata managed by Hive. External tables allow the data to remain at an externally maintained location while Hive manages the metadata.

// Q4. What is partitioning?

Partitioning divides a large dataset into smaller logical sections based on column values.

// Q5. What is bucketing?

Bucketing divides data into a fixed number of buckets using hashing.

// Q6. Partitioning vs Bucketing?


Partitioning
→ Based on values
→ Number of partitions depends on values

Bucketing
→ Based on hashing
→ Fixed number of buckets


// Q7. What is ORC?

ORC stands for Optimized Row Columnar. It is a columnar storage format optimized for analytical workloads in Hive.

// Q8. What is Parquet?

Parquet is a columnar storage format widely used for Big Data analytics.

// Q9. What is indexing in Hive?

Traditional Hive indexing was a feature intended to speed up searches on specific columns, but it was removed from Hive 3.0. Modern Hive uses mechanisms such as partitioning, bucketing, ORC/Parquet, predicate pushdown, and materialized views instead.

// Q10. What is LOAD DATA?

`LOAD DATA` loads a file from the local filesystem or HDFS into a Hive table.

// Q11. What is ALTER TABLE?

It modifies an existing Hive table, such as adding columns, renaming the table, or adding partitions.

// Q12. Difference between DROP and TRUNCATE?

`TRUNCATE` removes data while retaining the table. `DROP` removes the table itself.
